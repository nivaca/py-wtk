#+TITLE: Publishing py-wtk RPMs on Fedora COPR
#+AUTHOR: nivaca
#+STARTUP: overview

* Overview
COPR (https://copr.fedorainfracloud.org) builds RPMs from a source RPM
(SRPM) or straight from git, signs them with its own key, and publishes
them as a dnf repository.
- Project URL :: https://copr.fedorainfracloud.org/coprs/nivaca/py-wtk/
- Users install with :: =sudo dnf copr enable nivaca/py-wtk && sudo dnf install py-wtk=

There are two ways to submit builds:
1. *Upload an SRPM* built locally with =copr-cli=. This is the simplest way
   and gives full control. See [[*Workflow A: upload an SRPM]].
2. *SCM builds*: COPR clones the GitHub repo itself, and can rebuild on
   every push or tag through a webhook. See [[*Workflow B: build from git (optional)]].

* One-time setup
** 1. Fedora account
- Log in at https://copr.fedorainfracloud.org with your Fedora account
  (FAS, https://accounts.fedoraproject.org). Create one first if needed.

** 2. Install the client
#+begin_src sh
sudo dnf install copr-cli rpm-build rpmdevtools
#+end_src

** 3. API token
- Open https://copr.fedorainfracloud.org/api/ while logged in.
- Copy the block it shows into =~/.config/copr=:
#+begin_src conf
[copr-cli]
login = <shown on the page>
username = nivaca
token = <shown on the page>
copr_url = https://copr.fedorainfracloud.org
#+end_src
#+begin_src sh
chmod 600 ~/.config/copr
copr-cli whoami          # should print: nivaca
#+end_src
- *The token expires after 180 days.* The API page shows the expiry date.
  When it runs out, download a new block and replace the file.

** 4. Create the project
List the chroots (build targets) on offer, then create the project:
#+begin_src sh
copr-cli list-chroots | grep -E '^fedora-(4[5-9]|rawhide)-x86_64'

copr-cli create py-wtk \
  --chroot fedora-45-x86_64 \
  --chroot fedora-rawhide-x86_64 \
  --description "Look up words in the English Wiktionary: a command line, a terminal interface and a window." \
  --instructions "sudo dnf copr enable nivaca/py-wtk && sudo dnf install py-wtk" \
  --repo-priority 99
#+end_src
- The package is =noarch= (pure Python), so one architecture per Fedora
  release is enough: the x86_64 build installs on aarch64 too. The spec
  only needs python3-devel, desktop-file-utils and python3-tkinter, all in Fedora.
- Builds run without network by default (=--enable-net off=). That is
  fine here because nothing is downloaded during =%build=.
- You can also do all of this in the web UI: "New Project".

** 5. Signing key
All RPMs are signed with one key, the same on all the author's machines:
=81870643CA221AF90C30554EBE6832CD35994948= (Nicolas Vaughan, RPM signing, ed25519, 2026).
=build-rpm.sh= pins it (=SIGNING_KEY=); =--sign= uses only that key and stops
if it isn't in this machine's keyring, and =release.py= checks for it
first. A copy of the public key is in =packaging/RPM-GPG-KEY-py-wtk=; the
one exported next to the RPMs must match it. To set up another machine
(copy key.asc directly, by scp or USB, not through a synced folder):
#+begin_src sh
gpg --export-secret-keys --armor 81870643CA221AF90C30554EBE6832CD35994948 > key.asc   # where it is
gpg --import key.asc && shred -u key.asc                                            # on the new one
gpg --edit-key 81870643CA221AF90C30554EBE6832CD35994948 trust                        # 5 = ultimate
#+end_src

* Workflow A: upload an SRPM
** First release (or any release)
1. Make sure the tree is clean and committed. =build-rpm.sh= packs
   uncommitted changes too.
   #+begin_src sh
   git status --short        # should print nothing
   #+end_src
2. Build the SRPM, signed (always: the RPMs are always signed; gpg asks
   for the passphrase, so run it in a terminal). COPR signs its own builds
   with its own key too.
   #+begin_src sh
   packaging/build-rpm.sh --sign
   ls build/rpm/SRPMS/       # py-wtk-1.6-1.fc45.src.rpm
   #+end_src
3. Submit it:
   #+begin_src sh
   copr-cli build py-wtk build/rpm/SRPMS/py-wtk-*.src.rpm
   #+end_src
   - This waits and shows progress. Add =--nowait= to return at once.
   - Add =-r fedora-45-x86_64= (repeatable) to build only some chroots.
4. Check results:
   #+begin_src sh
   copr-cli list-builds nivaca/py-wtk
   copr-cli status <BUILD_ID>
   copr-cli watch-build <BUILD_ID>
   #+end_src
   Build logs (=builder-live.log=) are linked from the build's web page.
5. Test as a user would:
   #+begin_src sh
   sudo dnf copr enable nivaca/py-wtk
   sudo dnf install py-wtk      # or: sudo dnf upgrade py-wtk
   #+end_src

** Updating to a new version
1. Bump the version in =pywtk/__init__.py= as usual (and the docs), then
   the spec's, with a changelog entry, in =packaging/py-wtk.spec=:
   #+begin_src sh
   rpmdev-bumpspec -n 1.7 -c "Short description of the change" \
       -u "Nicolas Vaughan <nivaca@fastmail.com>" packaging/py-wtk.spec
   #+end_src
   =tools/release.py --rpm= stops while the two versions differ.
   - =-n VERSION= sets =Version:= and resets =Release:= to 1.
   - For a packaging-only fix with the same upstream version, leave out
     =-n=. That bumps =Release:= (1 → 2).
2. Commit, then publish with =tools/release.py --rpm=. Besides the
   tag and the releases, it builds the signed RPM (gpg asks for the
   passphrase), attaches it and its key to both releases, and sends the
   SRPM to COPR (=copr-cli build py-wtk build/rpm/SRPMS/py-wtk-X.Y-*.src.rpm=).
   =--no-copr= leaves that last step out; to do it by hand:
   #+begin_src sh
   packaging/build-rpm.sh --sign
   copr-cli build py-wtk build/rpm/SRPMS/py-wtk-1.7-*.src.rpm
   #+end_src
3. Users get it with =sudo dnf upgrade=. COPR regenerates the repo
   metadata after each build. dnf can take a while to notice, because of
   its metadata cache (=sudo dnf upgrade --refresh= forces a check).

*Rule:* each upload needs a higher Version-Release (EVR) than the last.
Otherwise dnf will not see it as an update.

* Workflow B: build from git (optional)
COPR clones github.com/nivaca/py-wtk and makes the SRPM itself.
=Source0= is a local tarball, so use the =make_srpm= method and a
=.copr/Makefile= in the repo. (Untested sketch: do the first SCM build by
hand before turning on the webhook.)

#+begin_src makefile
# .copr/Makefile — COPR runs: make -f .copr/Makefile srpm outdir=... spec=...
srpm:
	dnf -y install git rpm-build
	git config --global --add safe.directory "$$PWD"
	git rev-parse HEAD > COMMIT
	v=$$(rpmspec -q --srpm --qf '%{version}' $(spec)); \
	git archive --prefix=py-wtk-$$v/ --add-file=COMMIT \
	    -o $(outdir)/py-wtk-$$v.tar.gz HEAD; \
	rpmbuild -bs --define "_sourcedir $(outdir)" \
	    --define "_srcrpmdir $(outdir)" $(spec)
#+end_src
(Recipe lines must start with a TAB. COMMIT is what build-rpm.sh adds
too: the commit that "About" and =--version= show.)

Register the package:
#+begin_src sh
copr-cli add-package-scm py-wtk \
  --name py-wtk \
  --clone-url https://github.com/nivaca/py-wtk.git \
  --commit main \
  --spec packaging/py-wtk.spec \
  --method make_srpm \
  --webhook-rebuild on
#+end_src
- Manual build from the latest commit:
  =copr-cli build-package py-wtk --name py-wtk=
- Automatic builds: open Project → Settings → Integrations, copy the
  GitHub webhook URL, and add it in GitHub under Repo → Settings →
  Webhooks (content type =application/json=, "Just the push event", or
  pick "Branch or tag creation" to build only on tags).
- Change settings later with =copr-cli edit-package-scm py-wtk --name py-wtk ...=
- *Caution:* every push to =main= then makes a build. If =Release:= is
  not bumped, it has the same EVR as the last one and users do not get
  it. Either bump the spec with every pushed change, or point =--commit=
  at a release branch, or trigger on tags only.

* Maintenance
** New Fedora release / EOL
Add new chroots when Fedora branches, and drop EOL ones:
#+begin_src sh
copr-cli modify py-wtk \
  --chroot fedora-45-x86_64 --chroot fedora-46-x86_64 \
  --chroot fedora-rawhide-x86_64
#+end_src
(=--chroot= in =modify= *replaces* the whole list, so name all of them.)
Then rebuild the current SRPM so the new chroot has packages. Or, in the
web UI's "Regenerate"/"Fork" options for a new chroot, copy builds over
from a previous chroot.

** Housekeeping
#+begin_src sh
copr-cli list-builds nivaca/py-wtk
copr-cli cancel <BUILD_ID>
copr-cli delete-build <BUILD_ID>
copr-cli get nivaca/py-wtk          # project settings
#+end_src
- Renew the API token every 180 days ([[*3. API token]]).
- Failed builds: read =builder-live.log= on the build page, then fix and
  rebuild. To reproduce locally with the same setup:
  #+begin_src sh
  sudo dnf install mock && sudo usermod -aG mock $USER   # re-login
  mock -r fedora-45-x86_64 build/rpm/SRPMS/py-wtk-*.src.rpm
  #+end_src

* Quick reference: release checklist
- [ ] Bump =pywtk/__init__.py= (and the docs, NOTES)
- [ ] =rpmdev-bumpspec -n X.Y -c "..." packaging/py-wtk.spec=
- [ ] Commit; =tools/release.py --rpm --notes-file F= (tags vX.Y,
      publishes on both forges with the RPM, and builds it on COPR)
- [ ] =sudo dnf upgrade --refresh py-wtk= and smoke-test (=py-wtk -l la rosa=)
